# @swarmauth/core (TypeScript)

For production Node tools, use the `swarmauth` npm package in `js/`, which now
ships TypeScript declarations, guards, shared accounting, and async Redis support.
This package remains the portable protocol reference. It understands the
`shared_budget` wire constraint but does not reserve shared budgets or authorize
execution. Never substitute `verify` alone for execution-boundary enforcement.

TypeScript reference implementation of the SwarmAuth JSON Capability Token
(JCT) protocol. See the [top-level README](../README.md) for what SwarmAuth
is and why; see [SPEC.md](../SPEC.md) for the protocol itself, which this
package implements.

**Zero runtime dependencies.** Ed25519 via the standard Web Crypto API
(`globalThis.crypto.subtle`) -- works unmodified in Node.js 19+, browsers,
Deno, Bun, and Cloudflare Workers. No `npm install` of a crypto library
required.

## Status

Core protocol implementation: issue, verify, parse, one-hop attenuation,
issuer/holder key registries with rotation and revocation, token revocation,
and capability/parameter checks. It runs the same shared positive and
adversarial vectors as Python and Node.js, including `kid` binding,
delegation, malformed schemas, and Unicode issuance.

This package does **not** provide a usage tracker, issuer policy engine,
or framework guard. `verify` alone does not enforce call, rate, or spend
allowances. Use the Python SDK or the Node.js `swarmauth` package for a
complete execution-boundary integration; do not treat this core verifier
as authorization to execute a statefully limited tool.

## Quickstart

```typescript
import { KeyPair, issue, verify, checkCapability, checkParams } from "@swarmauth/core";

const toolKeys = await KeyPair.generate();

const token = await issue({
  issuerKeyPair: toolKeys,
  iss: "agent:requester-01",
  sub: "tool:process_payout",
  capabilities: ["tool:process_payout"],
  constraints: { allowedParams: { destination_account: "acct_1" } },
  ttlSeconds: 30,
});

// ... token travels to whatever verifies the tool call ...

const claims = await verify(token, {
  issuerPublicKey: toolKeys.publicBytes,
  audience: "tool:process_payout",
});
checkCapability(claims, "tool:process_payout"); // rejects a missing capability
checkParams(claims, { destination_account: "acct_1" }); // bind actual tool arguments
```

`issue`/`verify`/`sign` are `async` (Web Crypto's API is Promise-based);
everything else (`parse`, `checkCapability`, `checkParams`) is synchronous,
matching which operations touch the crypto layer in the Python SDK.

## A note on interop with the Python SDK's `KeyPair`

`KeyPair.fromPrivateBytes(seed)` accepts the same raw 32-byte Ed25519 seed
as Python's `KeyPair.from_private_bytes` / `.private_bytes` -- a key
generated by one SDK can be loaded by the other. Web Crypto has no `raw`
import format for Ed25519 *private* keys (only public keys), so this method
wraps the seed in a fixed, well-known 16-byte PKCS8/DER envelope before
handing it to `crypto.subtle.importKey` -- see the comment in
[`src/crypto.ts`](src/crypto.ts) for exactly why that's safe (Ed25519 has no
algorithm parameters, so the envelope is a constant).

## A note on canonical JSON

Every signature covers a canonical JSON encoding (SPEC.md §3.4): sorted
keys, no whitespace, non-ASCII escaped. `JSON.stringify` alone does neither
of the first two on its own terms needed here (key order, `ensure_ascii`
escaping) -- see [`src/canonicalJson.ts`](src/canonicalJson.ts), which
implements this explicitly and is the piece `spec/test-vectors` most
directly exercises. If you're porting SwarmAuth to a third language, this
file (and matching it against the vectors) is where to start.

Whole-number `maxAmountUsd` values are encoded as floats (e.g. `250.0`) to
match Python. Unicode is escaped by UTF-16 code unit and keys are sorted by
Unicode code point, including astral characters. Shared vectors test both
verification and byte-exact issuance.

## Delegation and revocation

`KeyRegistry.register(issuer, publicKey, { rotate: true })` retains old keys
through rotation; `registerHolder` authorizes a worker only to sign children.
Pass `keyRegistry` instead of `issuerPublicKey` to `verify` for delegation.
Use `attenuate({ issuerKeyPair, parent, iss, capabilities, constraints,
ttlSeconds })` to issue one narrower child. Verification checks both keys,
parent revocation, unchanged audience and pins, and narrower limits.

`InMemoryRevocationStore.revoke(jti, { expiresAt })` retains revocations
through the two-second grace period. Pass `revocationStore` to `verify`.
Custom stores may return a boolean or Promise<boolean> from `isRevoked`.
Leeway must be an integer from 0 to 2 seconds.

## Testing

```bash
npm test
```

Runs [`test/vectors.test.ts`](test/vectors.test.ts) against
`spec/test-vectors/vectors.json` using Node's built-in test runner (no
test-framework dependency either) -- including the temporal/leeway boundary
cases, using `node:test`'s built-in `Date` mocking rather than real sleeps.
