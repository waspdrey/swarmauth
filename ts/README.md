# @swarmauth/core (TypeScript)

TypeScript reference implementation of the SwarmAuth JSON Capability Token
(JCT) protocol. See the [top-level README](../README.md) for what SwarmAuth
is and why; see [SPEC.md](../SPEC.md) for the protocol itself, which this
package implements.

**Zero runtime dependencies.** Ed25519 via the standard Web Crypto API
(`globalThis.crypto.subtle`) -- works unmodified in Node.js 19+, browsers,
Deno, Bun, and Cloudflare Workers. No `npm install` of a crypto library
required.

## Status

Early. This is the core protocol only -- issue, verify, parse, capability
and parameter checks -- validated byte-for-byte against the same
[`spec/test-vectors/vectors.json`](../spec/test-vectors/) the Python SDK
enforces itself against (`npm test`). **Not yet ported from the Python
SDK:** `KeyRegistry` (multi-issuer trust + key rotation), `RevocationStore`,
distributed usage tracking, and framework adapters. Contributions welcome;
match the Python SDK's shape (`swarmauth/registry.py`,
`swarmauth/revocation.py`) rather than inventing a different API surface for
the same concept.

## Install

## Quickstart

```typescript
import { KeyPair, issue, verify, checkCapability } from "@swarmauth/core";

const toolKeys = await KeyPair.generate();

const token = await issue({
  issuerKeyPair: toolKeys,
  iss: "agent:requester-01",
  sub: "tool:process_payout",
  capabilities: ["tool:process_payout"],
  constraints: { maxAmountUsd: 1000, allowedParams: { destination_account: "acct_1" } },
  ttlSeconds: 60,
});

// ... token travels to whatever verifies the tool call ...

const claims = await verify(token, {
  issuerPublicKey: toolKeys.publicBytes,
  audience: "tool:process_payout",
});
checkCapability(claims, "tool:process_payout"); // throws CapabilityViolationError if not granted
```

`issue`/`verify`/`sign` are `async` (Web Crypto's API is Promise-based);
everything else (`parse`, `checkCapability`, `checkParams`) is synchronous,
matching which operations touch the crypto layer in the Python SDK.

## A note on interop with the Python SDK's `KeyPair`

`KeyPair.fromPrivateBytes(seed)` accepts the same raw 32-byte Ed25519 seed
as Python's `KeyPair.from_private_bytes` / `.private_bytes` -- a key
generated by one SDK can be loaded by the other. Web Crypto has no `raw`
import format for Ed25519 *private* keys (only public keys), so this method
wraps the seed in a fixed, well-known 16-byte PKCS8/DER envelope before
handing it to `crypto.subtle.importKey` -- see the comment in
[`src/crypto.ts`](src/crypto.ts) for exactly why that's safe (Ed25519 has no
algorithm parameters, so the envelope is a constant).

## A note on canonical JSON

Every signature covers a canonical JSON encoding (SPEC.md §3.4): sorted
keys, no whitespace, non-ASCII escaped. `JSON.stringify` alone does neither
of the first two on its own terms needed here (key order, `ensure_ascii`
escaping) -- see [`src/canonicalJson.ts`](src/canonicalJson.ts), which
implements this explicitly and is the piece `spec/test-vectors` most
directly exercises. If you're porting SwarmAuth to a third language, this
file (and matching it against the vectors) is where to start.

**Known limitation:** JavaScript's `number` type doesn't distinguish
`250.0` from `250` the way Python's `float`/`int` do, so a constraint value
that's a whole-number float (e.g. `max_amount_usd: 250.0`) will canonicalize
as `250`, not `250.0`, diverging from the Python SDK's output for that
specific value. Not exercised by the current vectors (which use `250.5`);
avoid whole-number floats in cross-checked fixtures until this is resolved.

## Testing

```bash
npm test
```

Runs [`test/vectors.test.ts`](test/vectors.test.ts) against
`spec/test-vectors/vectors.json` using Node's built-in test runner (no
test-framework dependency either) -- including the temporal/leeway boundary
cases, using `node:test`'s built-in `Date` mocking rather than real sleeps.
